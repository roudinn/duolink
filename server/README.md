# Сервис DuoLink

Сервис на Rust принимает запросы по HTTPS через nginx, хранит зашифрованную почту в SQLite и отвечает на STUN Binding по UDP. Локальные потоки Sunshine и Moonlight связываются через QUIC. Если прямой маршрут не устанавливается, резервный маршрут переносит пакеты QUIC через WebSocket по HTTPS.

`POST /signal/{topic}` принимает ключ каталога или зашифрованное сообщение. `GET /signal/{topic}/json` открывает подписку на NDJSON. Параметр `poll=1` возвращает только сохранённые записи. `since` принимает Unix-время в секундах или `all`. `GET /healthz` проверяет HTTP-сервис.

`GET /relay` открывает WebSocket для резервного маршрута. Ретранслятор допускает 48 открытых соединений, до пяти активных комнат и до четырёх гостей на комнату. Комната занимает слот, пока в ней есть хотя бы один гость. Действуют два лимита пересылаемого трафика с учётом служебных данных: около 8 Мбит/с на комнату и около 24 Мбит/с суммарно. При заполнении сервер отвечает `RelayFull`. Эти ограничения защищают ресурсы общего VPS. Видеопакеты и комнаты на диск не записываются.

На VPS HTTP слушает `127.0.0.1:8705`, STUN слушает UDP 3478 и 3479. Внешнее имя `duolink.154.86.119.7.sslip.io` проходит через существующий SNI-маршрутизатор nginx на `127.0.0.1:9464`. Разрешение на STUN ограничено двумя UDP-портами. nginx использует отдельный сертификат Let's Encrypt с webroot и перезагрузкой конфигурации после продления.

Сборка и тесты из корня репозитория.

```sh
cargo test --locked --manifest-path server/Cargo.toml
cargo build --release --locked --manifest-path server/Cargo.toml
```

Сервис запускается через [duolink.service](deploy/duolink.service). Бинарник устанавливается в `/opt/duolink/duolink-server`. Данные сервиса хранятся в `/var/lib/duolink`. Каталог хранится семь дней, личная почта двенадцать часов, адреса гостя для NAT-пробивки сорок секунд. База сохраняется при перезапуске.

## Нагрузка и обновление

Конфигурация в репозитории допускает 208 открытых подписок и до 320 одновременных запросов к сигналингу через nginx. Короткие всплески сглаживает ограниченная очередь SQLite. При обновлении конфигурации совместного VPS проверьте запас `worker_connections` и открытых файлов с учётом остальных сервисов. Длинная подписка проходит через TCP-прокси, HTTPS и HTTP-бэкенд и может занимать четыре соединения nginx.

Перед заменой сохраните копию бинарника и конфигурации nginx. Обновите только DuoLink, проверьте `nginx -t` перед перезагрузкой конфигурации и проверьте локальный и публичный `/healthz` после обновления.

После успешной проверки ветки `main` в GitHub Actions доступен архив `duolink-server-linux-x86_64` со сборкой для Ubuntu 24.04, конфигурацией и `SHA256SUMS`. Перед установкой проверьте файлы командой `sha256sum -c SHA256SUMS`.

Локальный тест поднимает сервер с отдельной базой и проверяет 100 одновременных регистраций, 200 подписок, запросы в друзья, обмен адресами для лобби, оба порта STUN и получение сообщений после переподключения.

```sh
node server/tests/capacity.mjs server/target/release/duolink-server
```

На Windows укажите путь к `duolink-server.exe`. GitHub Actions также прогоняет тест через nginx с TLS и TCP-прокси. Эти проверки измеряют нагрузку сигналинга. Пропускную способность резервной ретрансляции проверяют отдельно.

Для проверки рабочего VPS извне запустите вручную workflow `DuoLink server` или выполните `node server/tests/public-status.mjs`. Проверка делает один HTTPS-запрос и запрашивает ответ STUN на обоих портах.

[Зеркало](https://duolink.154.86.119.7.sslip.io/downloads/) отдаёт три закреплённых артефакта из `/srv/duolink/downloads`. При обновлении используйте [SHA256SUMS](deploy/SHA256SUMS), [страницу зеркала](deploy/downloads.html), оригинальные релизные бинарники и их лицензии. Драйвер Virtual HID Broker скачивается с сайта поставщика.
